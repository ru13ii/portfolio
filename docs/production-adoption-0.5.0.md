# 0.5.0 音楽空間デザインの正式採用

採用日: 2026-10-04

ユーザーがB案を正式採用し、GitHubへの反映と旧プロジェクトの削除を依頼した。作業用のGitリポジトリは従来のNew projectへ統一し、その内容を新デザインへ置き換える。比較用のRuBii Design Labは公開確認後に削除する。Git履歴は継続する。

## 現行の画面仕様

グランドピアノを上から見た構図にRuBiiの名義と紹介を載せ、左側に白鍵28・黒鍵20を描く。上部メニューはHome・Works・About・Contactの4白鍵と3黒鍵。黒鍵は独立したレイヤーでホバー時も欠けない。操作から新しい音符は生成せず、押下時だけの演出も使わない。

Homeの6つの音符はPCで常時ゆっくり漂う。スマホ・粗いポインター・ホバー不可・OSの動き削減では演出を止める。画面外・非表示タブでは浮遊を一時停止する。手動の停止ボタンは設けない。

Worksのジャンル選択は譜面の索引風の罫線・番号・選択下線を使う。WorksとAboutの下部にはContact誘導を置かない。Homeの問い合わせ導線と上部Contactメニューは維持する。

## 正式版として復元した機能

- Contactの送信先をJSONの既存Formspree受付URLへ接続。通常POSTとJavaScript送信、成功・エラー・利用制限時の表示を元の実装から引き継ぐ。
- 編集画面にGitHub保存用の入力欄とContents APIの保存処理を復元。GitHubの最新データが編集中の初期データと異なる場合は保存を拒否する。
- トークンをファイルや保存領域へ記録しない。JSONのダウンロードも維持する。
- GitHub Pagesの公開ワークフローを引き継ぎ、/portfolio/以下のパスをビルドで確認する。

試作版の資料は検討履歴として保存している。試作版の送信・保存の説明やローカル比較URLは現在の運用を示さない。この資料とREADMEを優先する。

## 検証

公開パス /portfolio/ でのビルドに成功。全5ページのナビゲーションとアイコンのパス、問い合わせのactionとPOST、編集画面のGitHub保存入力欄・保存用スクリプトを確認済み。トークン未入力時にAPIへ送信せず保存を阻止することもブラウザーで確認済み。新しいメールの実送信は今回行わず、接続済みの受付先を維持する。GitHubの公開処理と公開サイトを確認した後、比較コピーを削除する。

通常のGitプッシュはru13iiの認証が未設定で使用できなかったため、接続済みのGitHub連携で同じファイルを保存する。ファイルのGit blob SHAとtree SHAを照合して内容を一致させ、更新後はリモートを取得してローカルのmainを同期する。
