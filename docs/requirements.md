# 作曲家ポートフォリオサイト 要件整理

更新日: 2026-10-03  
状態: 初稿をGitHub Pagesで公開済み（フォームの送信・受信記録を確認済み）

## 1. サイトの目的と対象

### 確定事項

- 楽曲制作・BGM制作の依頼を獲得する。
- リスナーに作品を公開し、活動を発信する。
- 作曲家としての経歴を見てもらう。
- 日本語サイトとして始める。
- 活動名義の主表記は「RuBii」。日本語名義「るびぃ」の併記方法は初稿で検討する。

### 未確認

- 主な依頼主の想定（映像、ゲーム、配信、舞台、個人など）。
- 依頼獲得・試聴・経歴確認のうち、トップページで最も目立たせたい行動。

## 2. 掲載内容

### 確定事項

- 現在の作品は十数点。将来は約100作品まで増える可能性がある。
- オリジナル楽曲を作品として掲載する。作品のジャンル別絞り込みを設ける。
- ジャンルは「ポップス」「バラード」「エレクトロ」の3種類。
- 作品ごとに曲名、担当（作詞・作曲など）、作品種別・起用先を表示する。参考画像のように再生エリアと作品情報を組み合わせる。
- 作品、活動情報、経歴を掲載する。
- 音源の現在の形式・公開先はYouTube、SoundCloud、音声ファイル。
- 新たに掲載する音声ファイルはSoundCloudに統一する方向。YouTubeで公開中の動画は引き続き作品の再生先として使う。
- 本人の[YouTubeチャンネル「るびぃRuBii」](https://www.youtube.com/@ru13ii)への導線を設ける。
- トップページの代表曲は[「雨を待つ」](https://youtu.be/CxoTzLIx8Cs)。
- Xのプロフィールは[ru13ii_](https://x.com/ru13ii_)。サイト内の問い合わせフォームも設ける。
- フォームの受信先は提供済み。公開ページ、公開リポジトリ、要件書にはメールアドレスを直接記載しない。

### 初稿のページ構成

| 画面・区画 | 内容 |
| --- | --- |
| トップ | 作曲家名と紹介、代表作、お知らせ、制作依頼への導線を縦スクロールで見せる |
| Works | 上部メニューの「Works」から開く。オリジナル楽曲を大きな再生エリアと曲名・担当・起用先で見せ、ジャンルで絞り込む |
| About | プロフィールを掲載する。現時点では仮文を使用する |
| お知らせ | トップページに新作・活動情報を掲載し、編集ページから追加・変更できるようにする |
| Contact | Xへのリンクとサイト内問い合わせフォームの画面を掲載する |

作品が100点程度になっても探しやすい表示を想定する。ジャンル別絞り込みは実装済み。検索やページ分割の要否は、作品数が増えてから確認する。音声作品はSoundCloudの曲URLを使用し、YouTube動画も作品ごとに再生先として設定できる。

### ジャンル分類

ボカロPとしての作品を探しやすくするため、次の3分類を使う。編集ページで各作品のジャンルを選択できる。

- ポップス
- バラード
- エレクトロ

「使用した歌声合成音源」「ボーカル曲／インスト」などはジャンルとは別の属性として持たせる案。各作品にはまず一つのジャンルを設定する。

この文章はサイト初稿用のダミー文。本人が後で内容を見直し、エディットページから変更できるようにする。

## 3. デザイン

### 確定事項

- 方向性は「洗練された、おしゃれなデザイン」。
- [小川明夏さんのサイト](https://www.ogawasayaka.com/)を参考にする。
- トップページは縦にスクロールできる構成にしたい。
- 参考サイトからの細かな変更は、初稿を見てから考える。

### 参考サイトから読み取れる要素

余白を広く使ったレイアウト、淡い色調、文字を主役にしたトップ、明快なナビゲーションを参考候補とする。参考サイトの内容や見た目をそのまま複製するという意味ではない。

### 未確認

- 参考サイトで特に残したい要素と、初稿から変えたい要素。
- 色、字体、写真・イラストの使い方について、初稿を見た後の調整。

## 4. 自分で編集する仕組み

### 確定事項

- AIにサイトのUIと「エディットページ」を作ってもらう。
- サイト内のテキストなどを、本人が画面上で直接編集できるようにしたい。
- コンテンツ管理にはJSONを使う。
- 編集ページで保存した内容をGitHubのJSONへ直接反映し、公開サイトも更新したい。
- 編集ページは公開サイト上のURLから開けるようにしたい。

### 初稿での実装

GitHub Pagesは静的サイトの公開基盤なので、初稿ではFine-grained personal access tokenを編集ページで一時的に入力し、GitHub APIでJSONを更新する方法を採用した。トークンを公開コードやブラウザの保存領域に記録しない。

保存の流れ: 編集ページで内容を変更 → GitHubのJSONへ保存 → GitHub Actionsがサイトを再ビルド → GitHub Pagesへ公開。GitHubアカウントとリポジトリができた後に利用可能になる。

編集ページのURL自体は公開されるが、GitHubへの保存にはリポジトリの書き込み権限が必要。サイトの文章、作品、お知らせ、各種リンクを画面上で編集できる。作品の追加・削除・並び替え、JSONの書き出しもできる。画像ファイルの直接アップロードはまだ対象外。

## 5. 技術・公開方法

### 確定事項

- フレームワーク: Astro
- スタイル: Tailwind CSS
- コンテンツデータ: JSON
- 公開・管理: GitHub Pages / GitHubリポジトリ

### 初稿の構成

- Astroで静的ページを生成し、GitHub ActionsでビルドしてGitHub Pagesへ公開する。編集内容をGitHubへ保存した後も、この流れで反映する。
- 作品やプロフィールなどの編集可能な内容は、JSONのデータ構造を決めて管理する。
- リポジトリ名は `portfolio`、公開URLは `https://ru13ii.github.io/portfolio/`。ユーザーが作成した空のリポジトリを保存先として使う。独自ドメインの利用は後で決める。
- 音声ファイルはSoundCloudに置き、個別の曲URLを作品情報に設定する。GitHub Pagesに音声ファイルを直接置かない。
- サイト内フォームはFormspreeを接続済み。提供済みの受信先をサービス側で設定し、送信先URLをJSONに保存する。フォームとXを連絡窓口にする。公開サイトからの送信成功とFormspreeの受信一覧への記録を確認済み。本人からメールの到着も確認済み。
- GitHubアカウントは `ru13ii`。ユーザーからこのアカウントへサイトを置くよう依頼済み。GitHubプラグインとブラウザのログインを確認済み。リポジトリは `ru13ii/portfolio`。
- GitHub Pagesには商取引を主目的とするサイトに関する利用制限があるため、依頼受付の見せ方と公開先の適合性を制作前に確認する。

## 6. 制作品質の基本要件

- スマートフォンとパソコンの両方で読みやすく、操作しやすい。
- 作品名・試聴リンク・依頼窓口へ迷わずたどり着ける。
- キーボード操作、文字の読みやすさ、画像の代替テキストなど基本的なアクセシビリティに対応する。
- 作品追加時にレイアウトを作り直さず、JSONの追加・編集で更新できる構成にする。
