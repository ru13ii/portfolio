# B案の発展 — 触れると小さく動くピアノ楽譜

作成日: 2026-10-04
資料バージョン: 0.2.5
状態: デザイン・演出の提案。アニメーションは未実装。

更新案内（2026-10-04）: 本資料は初期検討の記録。[音楽空間とポートフォリオを一体化する改訂案](design-b-music-space.md)を現行案とする。スマホのタップ時の押下演出を含め、以下にあるスマホ向けアニメーション案は撤回し、サイト側の演出なしへ変更した。独立した楽譜の帯も、作品配置や操作と一体化する構成へ見直した。

## 1. 目指す体験

**「静かなピアノ楽譜に、触れたところだけ少し命が宿る」サイトにする。**

ユーザーが好意を示した[デザイン刷新案のB案](design-proposals-2026-10-04.md)を、ピアノ楽譜を中心とする方向へ発展させる。生成りの紙、大きな明朝体、細い罫線、広い余白を引き継ぎ、カーソルを合わせると小さな音符が反応する。

閲覧しているだけのときは、落ち着いた作品集。作品を選ぶときには、短い動きが返ってくる。楽譜らしさは、音符の数を増やすよりも、五線・小節の区切り・整った文字配置で表す。

技術的には、現在のAstroサイトにSVGの楽譜とCSSのアニメーションを組み合わせて実装できる。複雑な動画素材を作る必要はない。今回は構成と演出の提案までを整理する。

## 2. ピアノ楽譜をどう見せるか

### 基本の画面

トップでは大きな「RuBii」と短いコピーの下に、ト音記号とヘ音記号を持つ大譜表を一組置く。代表曲の紹介へ続く、幅の広い「楽譜の帯」として使う。作品の画像・曲名・試聴ボタンは、楽譜とは別の読みやすい場所に置く。

```text
［人物アイコン RuBii］                 Works About Contact

           感情豊かな
           音楽をお届けします。

    ┌─ 楽譜の帯：右手・左手の二段 ─────────────────┐
    │  右手の五線     … 数個の音符 …                │
    │  左手の五線     … 少数の和音 …                │
    └──────────────────────────────────────────────┘
       ↑ カーソルに近い一か所だけ、小さく反応する

    01  雨を待つ                             ［▶ 聴く］
    ┌──────────────────────────────────────────────┐
    │                 作品画像                     │
    └──────────────────────────────────────────────┘
         作詞・作曲 / 知声 / オリジナル楽曲
```

図は配置の説明であり、実際の採譜ではない。

### 本物の楽譜と装飾を分ける

- 初稿では、特定の曲を表さない装飾用の短い譜面を制作する。「雨を待つ」の実際の譜面とは表示しない。
- 音符・符尾・連桁・五線の形は統一し、音楽記号として不自然に崩さない。
- 本人のピアノ譜を使える場合は、その一部へ置き換えるとRuBii固有の表現になる。曲、抜粋範囲、正しい譜面を採用前に確認する。
- 実際の譜面を表示する場合は、音符の上下移動を使わず、色や小節単位の反応に切り替える。音高や拍の読み取りを邪魔しない。
- 楽曲の再生位置に追従する譜面や、自動採譜は別機能として扱う。今回の小さな装飾アニメーションには含めない。

## 3. おすすめのアニメーション

数値は初稿の調整用の目安。実際の画面で見て、必要ならさらに弱める。

| 場所 | きっかけ | 見える動き | 目安 | 優先度 |
| --- | --- | --- | --- | --- |
| トップの楽譜の帯 | ある小節にカーソルが入る | 近い音符1〜2個が少し浮き、元の位置へ戻る | 上下2〜3px、450〜600ms、1回 | 最優先 |
| Worksの「聴く」ボタン | ホバー／キーボードでフォーカス | ボタン脇の小さな音符が一度だけ揺れる。押せる範囲は動かない | 回転±3度以内、250〜350ms | 最優先 |
| ジャンルフィルター | クリック／タップ | 選んだラベルの下の短い線が、鍵盤を押したように1px沈んで戻る | 120〜180ms、1回 | 最優先 |
| トップの楽譜の帯 | 小節をホバー | 五線のうち一部分が薄い紫へ変わって戻る | 300〜450ms、音符の動きの代替 | 選択候補 |
| ナビゲーション | ホバー／フォーカス | リンクの下線が短く伸びる | 150〜200ms | 共通の操作表現 |
| 区画の見出し | 初めて画面に入る | 小さな小節番号が薄く現れる | 200ms程度、1回 | 初稿を見て判断 |

**初稿は「トップの音符」「聴くボタン」「フィルター」の3種類を中心にする。** 一つの要素に音符・五線・影・拡大を同時に重ねない。五線の色変化は、音符の上下移動と比べて採用する代替案とする。

### 体験A：音符が挨拶する

トップの小節へカーソルを合わせると、音符が2〜3pxだけふわっと浮き、ゆっくり元の位置に戻る。連桁でつながった音符は一つの組として動かし、符頭と符幹が離れないようにする。

カーソルを置き続けても繰り返さない。一度離れて再び入ると反応するが、同じ小節では前回の開始から800ms程度の間隔を空ける。速くカーソルを振っても動きが積み重ならない。

細い音符そのものを狙わせず、小節の領域で反応させる。小節は装飾なのでクリックを要求せず、クリック用の手形カーソルにも変えない。

### 体験B：試聴の入口が返事をする

「聴く」にカーソルを合わせると、横の小さな音符が一度だけ揺れる。曲名や文章、作品画像全体は動かさず、どこを押すかがすぐ分かるようにする。

ボタンを押したら、アニメーションの終了を待たずに試聴を開始する。埋め込みプレーヤーの読み込み待ちは通常の読み込み表示で伝え、装飾の動きだけを再生中の印にしない。

### 体験C：鍵盤のような選択感

ジャンルのラベルの下に短い線を置き、選択時にその線がわずかに沈む。ボタンの文字は固定したまま、短い押し心地だけを返す。

選択後は濃い下線とラベルの状態で区別する。全件・ポップス・バラード・エレクトロの機能は、従来と同じ分かりやすさを保つ。鍵盤の白鍵・黒鍵をそのままメニューにする必要はない。

## 4. ごちゃごちゃさせないためのルール

### 動かす範囲を限定する

1. **主な楽譜装飾はトップの一組。** ページ全体を五線柄で埋めない。
2. **待機中は静止。** 音符が漂い続ける、全カードが呼吸する、といった常時ループは初稿に入れない。
3. **大きな演出は同時に一か所。** カーソルが別の対象へ移ったら、前の装飾は短く静止状態へ戻す。通常の下線やフォーカス表示は維持する。
4. **一度に動く音符は1〜2個、連桁の場合は1組。** 周囲の音符は静止したままにする。
5. **アニメーションは原則600ms以内。** 長い余韻が残って次の操作と重ならないようにする。
6. **操作対象の位置と大きさを固定。** 揺らすのは内部の飾りだけにし、ボタンがカーソルから逃げないようにする。

### 見た目の情報量を抑える

- 背景は生成り、文字はインク色、反応色はくすんだ紫の3系統を基本にする。
- 五線は本文より薄く、音符は五線より少し濃くする。装飾の薄さを本文・ボタン・フォーカス枠へ適用しない。
- 楽譜を文章の背面に重ねない。コピーと譜面、譜面と作品情報の間には十分な余白を取る。
- 音符は画面上の飾りとして18〜26px程度から試す。実際の抜粋譜面では、五線との比率を優先して調整する。
- 人物アイコンと作品画像は元の色を生かし、周囲に同じ色の装飾を増やしすぎない。
- PCのポインターは通常の矢印を使う。カーソルを音符に変えたり、後ろへ音符を連続発生させたりしない。
- 花びら・粒子・音符の大量放出、強いバウンド、スクロールに追従する大きな傾きは初稿の対象外にする。

### 閲覧の目的を守る

曲名、担当、起用先、説明、試聴操作は常に表示する。ホバーしないと情報が出てこない構成にしない。問い合わせフォーム内は、入力状態・送信状態を示すための表現に絞り、音符を飛ばさない。

## 5. 音は鳴らすか

**初稿は音の出ないアニメーションを推奨する。** ポインターを動かしただけで音が鳴ると、作品の試聴や閲覧を妨げる可能性があるため、音を聴く行動は「聴く」ボタンへ集める。

将来、ピアノを弾く体験を加える場合は、独立した小さな「ピアノで遊ぶ」区画を候補にする。本人が有効にする操作、消音、音量、楽曲試聴との重なり方まで別途設計する。音を出す機能の採用は、今回の見た目の動きとは分けて決める。

## 6. スマートフォン・キーボード・動きを減らす設定

| 利用方法 | 提案する挙動 |
| --- | --- |
| マウス | 小節やボタンのホバーに局所的に反応する |
| タッチ | 楽譜の帯は静止。実際のボタンをタップしたときに小さな押下表現を返す |
| キーボード | 本物のリンク・ボタンにフォーカス枠を表示し、必要な演出だけホバーと同等に返す |
| 動きを減らす設定 | 浮遊・揺れ・移動を停止し、静的な下線・枠・選択状態で操作を示す |

スマートフォンにホバー操作や「一度触れて演出、二度目で実行」を要求しない。最初のタップで目的の操作ができるようにする。装飾の音符をキーボードの移動先に増やさない。

実装では、ホバー可能な入力機器に対象を限定するためのCSS条件と、OSの動きを減らす設定を参照するCSS条件を使う。これらの条件の役割は、[MDNのhover解説](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/hover)と[prefers-reduced-motion解説](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion)で確認した。端末名による一律の判定ではなく、入力方法と設定に合わせる。

## 7. 実装する場合の設計メモ

この節は開発者向け。利用者に表示する文言ではない。

- 楽譜はSVGで描き、五線・音符・小節を分けて扱う。最初は単純なSVGとCSSを使い、大きなアニメーションライブラリを導入しない。
- 音符の見た目は固定した図形でそろえる。端末によって形が変わる可能性がある絵文字を主な譜面として使わない。
- 音符の移動・回転は`transform`、濃淡は`opacity`や色の変化で表現する。本文の配置やボタンの幅を動かさない。
- ホバーは`(hover: hover)`を基本に、必要に応じて入力の細かさも条件にする。キーボードの`:focus-visible`は別途設計する。
- 繰り返し防止や対象の切り替えにだけ小さなJavaScriptを使う。画面全体のマウス座標を常時追い続ける構成は初稿に不要。
- 入力方法が変わった場合は、最後に操作された対象の装飾を優先する。見えていない領域の装飾は動かさない。
- ホバーが外れたときは200ms以内を目安に元の状態へ戻す。新しいアニメーションを無制限に追加しない。
- `prefers-reduced-motion: reduce`ではCSSの動きを止め、JavaScriptによる再生も開始しない。
- 装飾SVGは`aria-hidden="true"`とし、操作の名前は通常のボタン文字やラベルで伝える。実際の曲の譜面を情報として掲載する場合は、装飾とは別に曲名・抜粋範囲などの説明を用意する。
- iframeを表示した後は、周囲のホバー装飾がプレーヤーの操作に重ならないようにする。再生状態と演出を同期させるには別の設計が必要。
- 作品JSONや編集ページにアニメーション用の数値入力を増やさない。作者が普段編集する内容は、曲名・紹介文・担当・リンクなどに保つ。

## 8. 最初の試作と確認項目

最初はトップの楽譜一組、作品の試聴ボタン一個、ジャンルフィルターを試作する。画面全体へ展開する前に、この3か所で「小さく反応して楽しいか」「読んでいて気が散らないか」を確認する。

- 何も操作しなければ、音符は静止している。
- カーソルを素早く動かしても、音符の動きが連続して残らない。
- 文字や作品情報が隠れず、試聴・ページ移動・絞り込みをすぐ実行できる。
- ボタンの位置が動かず、誤クリックを起こさない。
- スマートフォンでは一度のタップで操作でき、横にはみ出さない。
- キーボード操作では現在地が見え、装飾のための余分な停止箇所がない。
- 動きを減らす設定では静止し、意味のある状態表示は残る。
- 作品が増えても、一覧全体が動き始めたり埋め込みを同時に読み込んだりしない。

## 9. 現時点の提案と未確定事項

おすすめは、**「静止した大譜表を一組＋近づくと返事をする音符＋鍵盤のような短い押下感」**。画面の骨格を楽譜らしく整え、遊び心を操作した場所に集中させる。

今回のユーザーの意向は「B案、とくにピアノ楽譜を主役にする方向が好み」「小さな動きとカーソルへの反応を検討したい」。以前のB案で提案した「動きは下線とフェードに絞る」という範囲を、この資料で広げている。

実装前に最終的に決めるのは、装飾譜面と本人の実際の譜面のどちらを使うか、初稿の動きが十分控えめかの2点。本人の譜面がなくても、装飾用の初稿は作れる。音を鳴らす体験は、追加したくなった時に別途検討する。
